RAUW Backend - Korte OWASP-, installatie- en deploymentnotities

1) OWASP Top 10 (backend) — wat is gedaan

A01 Broken Access Control
- Globale middleware blokkeert inactieve accounts op de meeste routes; gevoelige paden hebben een beperkte whitelist.
- Issue-leesrechten via visibility-scoping; onbevoegde toegang geeft vaak 404 i.p.v. 403 om bestaan niet te lekken.
- FormRequest-authorize op mutaties (issues, attachments, categories, districts) en officer Tier B/C voor workflow-routes.

A02 Cryptographic Failures
- Wachtwoorden worden via Laravel gehasht; tokens worden niet als platte tekst teruggegeven.
- Productie-deployment vereist APP_DEBUG=false zodat stacktraces niet naar clients lekken.

A03 Injection
- Database-toegang loopt via Eloquent/query builder met parameter binding.
- Invoer wordt per endpoint gevalideerd in FormRequests (types, enums, exists-regels).

A04 Insecure Design
- Issue-prioriteit wordt server-side afgeleid van categorie; clients mogen priority niet meesturen.
- Registratie gebruikt generieke foutmeldingen om e-mail-enumeratie te beperken.
- Inactieve accounts mogen profiel beperkt bijwerken (username/wachtwoord), niet alle velden.

A05 Security Misconfiguration
- Expliciete CORS-configuratie met alleen toegestane frontend-origins (geen wildcard).
- Sanctum token-expiratie via SANCTUM_TOKEN_EXPIRATION (standaard 7 dagen).
- Logout verwijdert alle tokens van de actor, niet alleen het huidige device.

A06 Vulnerable and Outdated Components
- (Geen specifieke backend-maatregelen in deze scope.)

A07 Identification and Authentication Failures
- Login weigert inactieve accounts met dezelfde generieke fout als ongeldige credentials.
- Bearer tokens verlopen; logout invalideert alle sessies van de actor.
- Rate limiting op gevoelige route-groepen (auth en beschermde API).

A08 Software and Data Integrity Failures
- Gevoelige modelvelden (bijv. created_by_manager_id, is_main_manager) niet vrij invulbaar via mass assignment.
- Department-koppelingen vereisen actieve departments bij toewijzing en registratie.
- Unieke database-index op issues.anonymous_alias met begrensde retry bij collision.

A09 Security Logging and Monitoring Failures
- Officer login/start-shift coördinaten worden vastgelegd op officer_sessions voor audit.
- API-fouten in productie geven generieke berichten; technische details horen in serverlogs.

A10 Server-Side Request Forgery (SSRF)
- (Geen relevante backend-endpoints die externe URLs ophalen op basis van client-input.)

Niet opgenomen in dit overzicht: open-officer-login en tijdelijk breder opengestelde manager-acties.

2) Installatie-instructies (backend)
1. Ga naar de backend-map:
   - cd apps/backend
2. Installeer dependencies:
   - composer install
3. Maak een lokale omgeving:
   - kopieer .env.example naar .env
4. Stel minimaal deze variabelen goed in:
   - APP_KEY (genereer met php artisan key:generate)
   - DB_CONNECTION en bijbehorende DB_* variabelen
   - SANCTUM_TOKEN_EXPIRATION=10080
   - FRONTEND_URL en FRONTEND_URL_PRODUCTION (voor CORS)
5. Zet database klaar:
   - php artisan migrate:fresh --seed
6. Start de backend lokaal:
   - php artisan serve --host=127.0.0.1 --port=8001

3) Deployment-instructies (backend)
1. Installeer productie-dependencies:
   - composer install --no-dev --optimize-autoloader
2. Zet productieconfiguratie correct:
   - APP_ENV=production
   - APP_DEBUG=false
   - APP_URL juist ingesteld
   - geldige DB-credentials
   - correcte SANCTUM- en CORS-variabelen
3. Voer migraties uit:
   - php artisan migrate --force
4. Optimaliseer caches:
   - php artisan config:cache
   - php artisan route:cache
   - php artisan view:cache
5. Controleer storage/symlink en rechten:
   - php artisan storage:link (indien nodig)
6. Controleer operationele processen:
   - queue workers en scheduler actief (indien gebruikt)

4) Belangrijke backend edge cases
- Inactieve accounts: kunnen op kritieke routes geblokkeerd worden terwijl beperkte self-service of auth-afhandeling beschikbaar blijft.
- Issue-zichtbaarheid: voor onbevoegde gebruikers wordt in sommige paden bewust 404 gebruikt in plaats van 403 om bestaan van records niet te lekken.
- Prioriteit op issues: wordt server-side afgeleid vanuit categorie/logica en is niet vrij te sturen door clients.
- Attachments: downloads en mutaties vallen onder autorisatieregels; bestanden zijn niet bedoeld als publiek toegankelijke assets.
- Unieke en gevoelige velden: uniciteit en validatie worden op backend- en databaseniveau afgedwongen om race conditions en inconsistente data te beperken.
- Mass assignment: systeemvelden blijven beschermd; alleen gecontroleerde velden mogen vanuit requests worden gezet.
